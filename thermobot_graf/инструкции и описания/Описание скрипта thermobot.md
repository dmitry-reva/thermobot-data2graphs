Cкрипт представляет собой **конфигурационный блок для утилиты
logrotate** --- инструмента, который автоматически управляет ротацией
(архивацией и очисткой) лог‑файлов в Linux.

Конфигурационный блок описывает правила обработки файлов,
соответствующих шаблону /var/log/thermobot_logs/\*.log.

**Разбор параметров**

- /var/log/thermobot_logs/\*.log --- шаблон, указывающий на все
  .log-файлы в директории /var/log/thermobot_logs/.

- daily --- ротация логов будет выполняться **ежедневно**.

- rotate 30 --- сохраняется **30 последних версий** ротированных логов,
  после чего старые архивы удаляются.

- delaycompress --- сжатие (архивирование) логов откладывается до
  следующей ротации. Это снижает нагрузку при активной записи в лог.

- missingok --- если целевой лог‑файл отсутствует, logrotate **не выдаст
  ошибку**, а просто пропустит его.

- notifempty --- лог будет ротирован только если он **не пустой**.

- create 0640 dmr root --- после ротации создаётся **новый пустой
  лог‑файл** с:

  - правами доступа 0640 (владелец может читать и писать, группа ---
    только читать, остальные --- без доступа);

  - владельцем dmr;

  - группой root.

**Цель конфигурации**

Обеспечить:

- регулярную ротацию логов термоботов;

- контроль объёма хранимых данных (ограничение 30 версиями);

- безопасность доступа к логам (за счёт прав 0640);

- стабильность работы (игнорирование отсутствующих или пустых файлов).

**Инструкция по установке**

**Шаг 1. Убедитесь, что logrotate установлен**

Проверьте наличие logrotate:

logrotate \--version

Если утилита не установлена:

- для Ubuntu/Debian:

- sudo apt update && sudo apt install logrotate

- для CentOS/RHEL:

- sudo yum install logrotate

**Шаг 2. Создайте конфигурационный файл**

Добавьте описанный блок в конфигурационный файл logrotate.\
Обычно новые правила добавляют в /etc/logrotate.d/, создав отдельный
файл, например:

sudo nano /etc/logrotate.d/thermobot-logs

Вставьте содержимое:

/var/log/thermobot_logs/\*.log {

daily

rotate 30

delaycompress

missingok

notifempty

create 0640 dmr root

}

Сохраните файл (в nano: Ctrl+O, введите имя файла, нажмите Enter).

**Шаг 3. Проверьте синтаксис конфигурации**

Убедитесь, что файл записан без ошибок:

sudo logrotate \--debug /etc/logrotate.d/thermobot-logs

Ошибки в синтаксисе выведутся в консоль. Исправьте их при необходимости.

**Шаг 4. Примените ротацию вручную (для тестирования)**

Чтобы проверить, что правила работают, выполните:

sudo logrotate /etc/logrotate.d/thermobot-logs

Убедитесь, что:

- исходный лог‑файл заархивирован (получит суффикс .1, .2 и т. д.);

- создан новый пустой лог‑файл с корректными правами (0640, владелец
  dmr, группа root).

**Шаг 5. Настройте автоматический запуск (если не работает по
умолчанию)**

Logrotate обычно запускается автоматически через cron (ежедневно).\
Проверьте, что задача есть в планировщике:

crontab -l \| grep logrotate

Типичный вариант записи в crontab:

25 6 \* \* \* root logrotate /etc/logrotate.conf

(запуск в 6:25 ежедневно).

Если задачи нет, добавьте её вручную через sudo crontab -e.

**Важные замечания**

- Убедитесь, что директория /var/log/thermobot_logs/ существует и
  доступна для записи пользователю dmr.

- Проверьте, что приложения, пишущие в логи, используют именно эту
  директорию.

- При изменении конфигурации **перезапуск сервисов не требуется** ---
  logrotate подхватывает изменения при следующем запуске.

- Для отладки можно временно раскомментировать #debug в основном конфиге
  (/etc/logrotate.conf), чтобы включить подробный вывод.
