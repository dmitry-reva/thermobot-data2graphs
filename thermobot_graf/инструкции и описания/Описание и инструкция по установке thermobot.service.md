Данный скрипт представляет собой **юнит-файл systemd** (.service),
предназначенный для управления запуском Python-скрипта
plot_temperatures.py в рамках окружения проекта thermobot_graf.

**Разбор секций скрипта**

1.  **\[Unit\]**

    - Description=Thermobot Graf --- краткое описание сервиса.

    - After=network.target --- указывает, что сервис должен запускаться
      после инициализации сетевого стека системы.

2.  **\[Service\]**

    - User=dmr --- сервис будет выполняться от имени пользователя dmr.

    - WorkingDirectory=/opt/thermobot_graf --- рабочая директория
      сервиса (где находятся файлы проекта).

    - Environment=\"PATH=/opt/thermobot_graf/venv/bin\" --- задаёт
      переменную окружения PATH, указывая на бинарные файлы виртуального
      окружения Python. Это необходимо для корректного использования
      установленных зависимостей.

    - ExecStart=/opt/thermobot_graf/venv/bin/python3
      /opt/thermobot_graf/plot_temperatures.py --- команда для запуска
      скрипта:

      - используется интерпретатор Python из виртуального окружения
        (venv/bin/python3);

      - выполняется скрипт plot_temperatures.py, расположенный в рабочей
        директории.

    - Строка \# Restart=always закомментирована --- при
      раскомментировании сервис будет автоматически перезапускаться при
      любом завершении (включая аварийное).

3.  **\[Install\]**

    - RequiredBy=thermobot.timer --- связывает сервис с таймером
      thermobot.timer, который, вероятно, отвечает за периодический
      запуск сервиса.

Инструкция по установке thermobot.service

**Шаг 1. Сохраните юнит-файл**

Сохраните содержимое скрипта в файл с именем thermobot.service в
директории /etc/systemd/system/:

sudo nano /etc/systemd/system/thermobot.service

Вставьте текст скрипта и сохраните файл (в редакторе nano --- нажмите
Ctrl+O, введите имя файла, затем Enter).

**Шаг 2. Проверьте корректность файла**

Убедитесь, что файл записан без ошибок, выполнив:

systemctl validate /etc/systemd/system/thermobot.service

Если ошибок нет, команда не выведет сообщений.

**Шаг 3. Перезагрузите конфигурацию systemd**

Чтобы systemd распознал новый юнит, выполните:

sudo systemctl daemon-reload

**Шаг 4. Запустите сервис**

Запустите сервис вручную для проверки:

sudo systemctl start thermobot.service

Проверьте статус сервиса:

sudo systemctl status thermobot.service

В выводе должно быть указано active (running).

**Шаг 5. Настройте автоматический запуск (опционально)**

Если нужно, чтобы сервис запускался при загрузке системы, выполните:

sudo systemctl enable thermobot.service

**Шаг 6. Проверьте логи (при необходимости)**

Если сервис не запускается, посмотрите логи:

journalctl -u thermobot.service -b -n 50

Флаг -b показывает логи с момента последней загрузки, -n 50 ---
последние 50 записей.

**Важные замечания**

- Убедитесь, что:

  - директория /opt/thermobot_graf/ существует;

  - у пользователя dmr есть права на чтение/запись в эту директорию;

  - виртуальное окружение (venv) создано и активировано;

  - скрипт plot_temperatures.py присутствует в рабочей директории и не
    содержит ошибок.

- Если вы раскомментируете Restart=always, сервис будет перезапускаться
  даже при критических ошибках --- используйте с осторожностью.
