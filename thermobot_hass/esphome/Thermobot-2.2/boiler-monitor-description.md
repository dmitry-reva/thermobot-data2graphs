# Boiler Monitor (Thermobot-2.2): описание конфигурации

Файл конфигурации: `boller-monitor.yaml` (ESPHome, ESP8266).
Имя устройства в ESPHome: `boiler-monitor`, имя в Home Assistant: «Boiler Monitor».

> **Статус.** Конфигурация новая и **в ESPHome ещё не собиралась**. Проверены: синтаксис YAML, подстановки, ссылки на `id`, а лямбды дисплея и тревог откомпилированы на заглушках и прогнаны на примерах. Версия ESPHome: 2026.9.1 и новее (рекомендуется 2026.10+). Стиль и структура взяты из `heatflow_1.yaml`, распиновка из `thermobot-ds.yaml`.

## 1. Назначение

Контроль котла на твёрдом топливе: пять датчиков температуры DS18B20, трёхразрядный семисегментный дисплей, местная сигнализация (зуммер и светодиод) и передача данных в Home Assistant.

| Датчик | Что измеряет | Метка на дисплее |
|---|---|---|
| Outdoor | уличный воздух | `Out` |
| Supply | подача теплоносителя | `SUP` |
| Return | возврат теплоносителя | `rEt` |
| Auger | температура шнека | `Aug` |
| Hopper | воздух в бункере | `Hop` |

Для каждого датчика есть **ручная калибровка** и **свои границы тревоги**.

## 2. Оборудование и пины

| Пин | Назначение | Примечание |
|---|---|---|
| GPIO0 | линия 1-Wire (все 5 датчиков на одной шине) | strapping-пин; обязательна подтяжка 4,7 кОм к 3,3 В |
| GPIO2 | светодиод | инверсная логика, при загрузке должен быть HIGH |
| GPIO4 | TM1637 CLK | |
| GPIO5 | TM1637 DIO | |
| GPIO12 | пассивный зуммер | программный ШИМ (`esp8266_pwm`) |

Аппаратных кнопок нет: GPIO14 не используется. Управление дисплеем целиком вынесено в сущности Home Assistant и веб-интерфейс.

Плата: `nodemcuv2`, `restore_from_flash: true` (настройки и калибровки переживают потерю питания).

## 3. Режим отображения (без кнопок)

Дисплей работает автоматически, а настраивается через сущности.

### 3.1. Как это выглядит

- **Проверка после включения:** 1,5 с горит `888`.
- **Страница датчика** = метка (по умолчанию 1 с), затем значение (по умолчанию 3 с). Например: `SUP` → `65.3`.
- **Автокарусель (`Display mode` = `Auto`):** датчики показываются по очереди в порядке Out → SUP → rEt → Aug → Hop. При настройках по умолчанию страница длится 4 с, полный круг 20 с.
- **Фиксированный датчик:** `Display mode` = `Outdoor` / `Supply` / `Return` / `Auger` / `Hopper`. Показывается только этот датчик, его метка периодически выводится на 1 с.
- **Тревога приоритетнее режима:** если хотя бы один датчик вышел за свои границы, дисплей показывает только датчики в тревоге, а их значение **мигает** (период 500 мс). Это работает в любом режиме, поэтому фиксированная страница тревогу не скроет. Кнопка `Acknowledge alarm` гасит только звук и светодиод, мигание на дисплее остаётся, пока температура не вернётся в норму.
- **Датчик недоступен:** `---` в первые 20 с после загрузки, затем `Err`.

### 3.2. Формат чисел

| Значение | Показывается | Пример |
|---|---|---|
| от −9,9 до 99,9 | одна десятая | `23.5`, ` 5.3`, `-9.9` |
| 100 и больше, −10 и меньше | целое | `100`, `-12` |

Десятичная точка занимает ту же ячейку, что и цифра, поэтому все значения помещаются в три разряда.

### 3.3. Параметры дисплея

| Сущность | Диапазон | По умолчанию |
|---|---|---|
| Display mode (select) | Auto / Outdoor / Supply / Return / Auger / Hopper | Auto |
| Display page time | 1–30 с | 3 |
| Display brightness | 1–8 | 6 |

Время показа метки (1000 мс), метки датчиков (до 3 символов) и переворот дисплея (`display_inverted`) задаются в блоке `substitutions`.

Карусель привязана к времени работы устройства, а не хранит состояние: при смене режима или состава датчиков в тревоге страница может «перескочить», это нормально.

## 4. Датчики и калибровка

Опрос каждого датчика: каждые 10 с (`temp_update_interval`). Значение на выходе:

```
значение = измеренное + калибровка датчика
```

| Сущность | Диапазон | По умолчанию |
|---|---|---|
| Outdoor calibration | ±10 °C, шаг 0,1 | 0 |
| Supply calibration | ±10 °C, шаг 0,1 | 0 |
| Return calibration | ±10 °C, шаг 0,1 | 0 |
| Auger calibration | ±10 °C, шаг 0,1 | 0 |
| Hopper calibration | ±10 °C, шаг 0,1 | 0 |

Новая калибровка применяется со следующего измерения (до 10 с). И дисплей, и тревоги работают уже по откалиброванным значениям.

Дополнительно: `Delta temperature` (подача минус возврат), `WiFi Signal`, `Uptime`.

## 5. Тревоги

У каждого датчика свои нижняя и верхняя границы. Тревога включается через 5 с после выхода за границу и выключается через 30 с после возврата в норму (защита от дребезга).

| Датчик | Нижняя | Верхняя | Комментарий |
|---|---|---|---|
| Outdoor | −55 | 125 | границы на всём диапазоне DS18B20, то есть тревога выключена |
| Supply | 5 | 90 | как в HeatFlow |
| Return | 5 | 90 | как в HeatFlow |
| Auger | −55 | 60 | **стартовое значение**, задайте по паспорту котла |
| Hopper | −55 | 50 | **стартовое значение**, задайте по паспорту котла |

Значения лежат в `substitutions` и меняются потом из Home Assistant (диапазон −55…125 °C, шаг 0,1). Нижняя граница −55 или верхняя 125 фактически отключают соответствующий порог.

Сущности:
- Бинарные датчики тревоги по датчикам: `Outdoor alarm`, `Supply alarm`, `Return alarm`, `Auger alarm`, `Hopper alarm`.
- Общий `Temperature alarm`: включён, если тревога у любого датчика. Он запускает и останавливает местную сигнализацию.
- `Temperature sensor fault`: любой датчик не читается (после 90 с с момента загрузки).
- Пока общая тревога активна: мигание светодиода и сигнал зуммера, повтор каждые `Alarm repeat interval` (1–86400 с, по умолчанию 60).
- Недоступный датчик (NaN) тревоги по температуре **не вызывает**, он отражается только в `Temperature sensor fault`.

## 6. Звук

Зуммер пассивный, управляется напрямую через ШИМ. Сигнал по умолчанию такой же, как у исходной прошивки Thermobot (`tone` 3000 Гц, 100 мс).

| Сущность | Диапазон | По умолчанию |
|---|---|---|
| Sound (выключатель) | вкл / выкл | вкл |
| Sound volume | 0–100 % | 100 |
| Sound frequency | 500–5000 Гц | 3000 |
| Sound duration | 20–2000 мс | 100 |
| Beep test (кнопка) | пробный сигнал, выключатель Sound не учитывает | |

- **Громкость** задаёт амплитуду сигнала: 100 % соответствует скважности 50 %, это максимум для прямоугольного сигнала. Выше 100 % громкость программно поднять нельзя.
- **Реально влияет на громкость частота:** пьезозуммер громче всего звучит на частоте резонанса (обычно 2–4 кГц). Нажимайте `Beep test` и подберите `Sound frequency`.
- Звук включается при старте, при подключении к Wi-Fi и при тревоге, если `Sound` включён.
- Программный ШИМ на ESP8266 может потрескивать при высокой Wi-Fi-активности.

## 7. Остальные сущности

| Тип | Сущности |
|---|---|
| Выключатели | `LED` (ручное управление светодиодом), `Sound` |
| Кнопки | `Beep test`, `Acknowledge alarm`, `Restart`, `Safe mode` |
| Диагностика | `Status`, `IP Address`, `SSID`, `BSSID`, `ESPHome Version` (по умолчанию скрыт) |

Что осознанно **не** включено: Telegram, перезагрузка Wi-Fi по таймеру, аппаратная кнопка.

Сеть и доступ как в HeatFlow: точка доступа `Boiler Monitor` (пароль `web_server_pass`), `captive_portal`, `web_server` v2 с digest-авторизацией на порту 80, API с шифрованием, OTA, `safe_mode`.

## 8. Ввод в эксплуатацию

1. **Секреты** (`secrets.yaml`): `wifi_0f`, `wifi_password`, `web_server_pass`, `api_key`.
2. **Подтяжка** линии 1-Wire (GPIO0) 4,7 кОм к 3,3 В должна быть на плате.
3. **Адреса DS18B20.** Все пять датчиков на одной шине, поэтому адрес нужен каждому. В файле стоят заглушки (`0x…0128` … `0x…0528`) с пометкой «требует замены».
   1. Временно поставьте `logger: level: DEBUG`.
   2. Подключайте датчики **по одному** и фиксируйте адрес в логе, чтобы знать, какой датчик на каком месте.
   3. Впишите адреса в `addr_outdoor`, `addr_supply`, `addr_return`, `addr_auger`, `addr_hopper`.
   4. Верните `level: WARN`.
4. **Первая сборка:** сборка и прошивка по кабелю, затем обновления по OTA.
5. **Настройка в Home Assistant:** границы тревоги Auger и Hopper по паспорту котла, калибровка каждого датчика по эталонному термометру, громкость и частота зуммера, время страницы и яркость дисплея.

## 9. Допущения и что проверить

| Вопрос | Статус |
|---|---|
| Сборка конфигурации в ESPHome | не проверялась, проверить при первой сборке |
| Адреса датчиков | заглушки, обязательно заменить |
| Пороги Auger (60 °C) и Hopper (50 °C) | стартовые значения, подобрать по паспорту котла |
| Трёхразрядный TM1637 на GPIO4/GPIO5 | пины взяты из `thermobot-ds.yaml`; порядок разрядов и ориентацию проверить на плате (`display_inverted`) |
| Вид букв `Out`, `SUP`, `rEt`, `Aug`, `Hop` | зависит от шрифта TM1637, проверить на модуле, метки меняются в `substitutions` |
| Тип зуммера | рассчитан на пассивный; на активном громкость и частота не регулируются |
| Один отсутствующий датчик | `Temperature sensor fault` будет включён постоянно, а на дисплее у этого датчика `Err`: конфигурация рассчитана на все пять датчиков |

## 10. Подключение к Home Assistant

### 10.1. Добавление устройства

1. Устройство должно быть в одной сети с Home Assistant. Обычно оно обнаруживается само: **Настройки → Устройства и службы** → карточка «Обнаружено: ESPHome (Boiler Monitor)» → **Настроить**.
2. На вопрос о ключе шифрования введите значение секрета `api_key` из вашего `secrets.yaml`.
3. Если устройство не обнаружилось: **Добавить интеграцию → ESPHome**, хост `boiler-monitor.local` (или IP-адрес), порт `6053`.
4. Укажите область (в конфигурации задано `area: "Boiler room"`, при необходимости подставьте свою).

Идентификаторы сущностей строятся из имени устройства и имени сущности, например `sensor.boiler_monitor_supply_temperature` или `binary_sensor.boiler_monitor_temperature_alarm`. Сущности калибровки, границ, звука и дисплея относятся к категории «Конфигурация» или «Диагностика»: в автоматически созданных панелях их нет, они видны на странице устройства. В карточке ниже они выведены явно.

### 10.2. Карточка Lovelace

Файл `boiler-monitor-lovelace.yaml` содержит одну карточку из встроенных (HACS не нужен): **панель → Изменить → + Добавить карточку → Вручную** → вставить весь текст.

В карточке:
- **Баннер тревоги.** Виден только при общей тревоге и перечисляет датчики, вышедшие за границы, с их значениями. Отдельный баннер появляется при отказе датчика.
- **Температуры:** шесть плиток (улица, подача, возврат, шнек, бункер, разность подача-возврат).
- **Тревоги:** общая и по каждому датчику, отказ датчика, кнопка «Подтвердить», выключатель звука и выбор режима дисплея.
- **График** пяти температур за 24 часа.
- **Калибровка и границы:** все числовые настройки (калибровки, границы тревоги, интервал повтора, время страницы и яркость дисплея, громкость, частота и длительность сигнала) и кнопка пробного сигнала.

### 10.3. Уведомление о тревоге

Файл `boiler-monitor-automation.yaml`: **Настройки → Автоматизации → Создать → ⋮ → Редактировать в YAML** → вставить. Автоматизация срабатывает, когда общая тревога держится 30 с, и отправляет сообщение вида «Шнек: 61.2 °C, Бункер: 55.3 °C». Службу `notify.notify` замените на свою (например, `notify.mobile_app_<имя телефона>`).

### 10.4. Что учесть

- Если вы переименовали устройство или сущности, обновите идентификаторы в карточке и автоматизации (**Настройки → Устройства и службы → ESPHome → Boiler Monitor**).
- Звук и мигание светодиода работают на устройстве автономно: при недоступности Home Assistant тревога всё равно срабатывает (`api.reboot_timeout: 0s`, перезагрузки при потере связи нет).
- Кнопка «Подтвердить» гасит только звук и светодиод. Мигание значения на дисплее и состояние тревоги в Home Assistant сохраняются, пока температура не вернётся в норму.
- Значения чисел, изменённые из панели, запоминаются на самом устройстве и переживают отключение питания.
