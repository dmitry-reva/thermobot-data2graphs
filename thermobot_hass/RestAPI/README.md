# Thermobot в Home Assistant через REST API

Этот вариант позволяет Home Assistant получать температуру с устройства
Thermobot, на котором оставлена заводская прошивка. Home Assistant периодически
опрашивает HTTP-адрес `/read`; перепрошивать устройство не требуется.

> **Legacy-вариант.** Рекомендуемый способ интеграции — ESPHome: он избавляет от
> ручного управления IP-адресами и предоставляет больше настроек и сущностей.
> Используйте REST API, если устройство нельзя или не хочется перепрошивать.
> Инструкция по ESPHome находится в [../esphome/README.MD](../esphome/README.MD).

Готовый фрагмент конфигурации находится в
[configuration.yaml](configuration.yaml). Это пример для объединения с
конфигурацией Home Assistant, а не готовый файл для замены существующего.

## Как работает интеграция

Для каждого устройства создаётся REST-сенсор, обращающийся к адресу вида
`http://<IP-адрес>/read`. В примере настроены два сенсора:

- опрос каждые 90 секунд;
- таймаут HTTP-запроса 20 секунд;
- извлечение температуры из ответа регулярным выражением;
- публикация состояния в Home Assistant с единицей `°C` и классом устройства
  `temperature`.

В конфигурации также есть MQTT-сенсор с топиком
`homeassistant/sensors/temperature`. Он **подписывается** на этот топик, но не
публикует в него значения и не объединяет показания REST-сенсоров. Для получения
состояния у этого MQTT-сенсора нужен отдельный издатель и настроенный в Home
Assistant MQTT-брокер. Если MQTT не используется, удалите раздел `mqtt` из
конфигурации.

## Установка

1. Зарезервируйте постоянный IP-адрес для каждого Thermobot в настройках
   маршрутизатора. REST-датчик привязан к IP: если адрес устройства изменится,
   запросы перестанут получать актуальные данные.
2. Откройте `configuration.yaml` Home Assistant и перенесите в него разделы
   `sensor:` и (если нужен) `mqtt:` из
   [готового фрагмента](configuration.yaml). Не заменяйте ими весь свой файл.
   Если в конфигурации уже есть раздел `sensor:`, объедините записи в одном
   списке, не создавая второй раздел с тем же ключом верхнего уровня.
3. Замените `IP1` и `IP2` на адреса ваших устройств. Если используется только
   один Thermobot, удалите блок второго REST-сенсора.
4. Настройте MQTT-интеграцию и внешний издатель данных, только если нужен
   MQTT-сенсор из примера. Его топик и формат сообщения должны соответствовать
   настройкам издателя.
5. Проверьте конфигурацию Home Assistant и перезапустите его, чтобы применить
   YAML-изменения.

До добавления датчиков проверьте доступность адресов в локальной сети,
открыв `http://<IP-адрес>/read` в браузере или выполнив HTTP-запрос.

## Извлечение температуры

Шаблон из примера:

```yaml
value_template: "{{ value | regex_findall('\\d+\\.\\d+') | first | float }}"
```

Он рассчитан на ответ, содержащий положительное десятичное число с точкой,
например `23.5`. Он не учитывает знак минус и не находит целые числа без
десятичной части. Если ответ вашей прошивки отличается, адаптируйте шаблон к
его фактическому формату и проверьте показания, включая отрицательную
температуру и ошибку датчика, прежде чем полагаться на сенсор.

## Проверка

После перезапуска откройте **Настройки → Устройства и службы → Сущности** и
найдите REST-сенсоры по заданным именам (в примере — «Название датчика 1» и
«Название датчика 2»). Убедитесь, что состояния обновляются и показывают
ожидаемую температуру. При ошибке проверьте IP-адрес, доступность `/read` и
соответствие `value_template` формату ответа.

MQTT-сенсор проверяйте отдельно: подтвердите, что издатель отправляет данные в
`homeassistant/sensors/temperature`, а MQTT-интеграция подключена к брокеру.
Наличие REST-сенсоров само по себе не приводит к публикации данных в MQTT.

## Ограничения

- Требуется поддерживать актуальные IP-адреса устройств (рекомендуется DHCP-
  резервирование на маршрутизаторе).
- Значения обновляются только при очередном опросе; задержка может достигать
  интервала сканирования плюс время ответа устройства.
- Регулярное выражение из примера подходит только для указанного формата
  положительной десятичной температуры.
- MQTT-раздел — независимый подписчик, а не мост между REST-сенсорами и MQTT.
- REST-вариант даёт только чтение температуры. Для калибровки, тревог,
  диагностики, OTA и более полной интеграции используйте
  [ESPHome](../esphome/README.MD).
